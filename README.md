# Monthly Stock Returns Forecasting (XGBoost + CatBoost + Optuna, GPU)

Скрипт строит **месячный панель признаков** по OHLCV данным акций и обучает две модели регрессии:

* **XGBoost (GPU)** + подбор гиперпараметров через **Optuna**
* **CatBoost (GPU)** + подбор гиперпараметров через **Optuna**

Цель: прогноз **доходности следующего месяца** (`target_next`) на базе расширенного набора признаков:

* лаги месячных лог-доходностей,
* rolling mean/std/momentum,
* ATR (Wilder),
* RSI (Wilder),
* изменения объёма,
* рыночный фактор (equal-weight),
* календарные sin/cos по месяцу.

Далее имитируется “онлайн”-сценарий: **предсказали месяц → добавили этот месяц в train → дообучили/переобучили модель**.

---

## Как работает код (по шагам)

Ниже — «карта местности», чтобы было понятно, что именно делает скрипт и в каком порядке.

### Шаг 0. Конфиг и параметры эксперимента

В начале файла задаются:

* пути (`DATA_DIR`, `ALL_CSV`),
* правила выбора цены (`PRICE_COL_PREF`),
* границы разбиения на Train/Test/Valid (`TRAIN_END`, `TEST_YEAR`, `VAL_YEAR`),
* число trial’ов Optuna (`N_TRIALS_XGB`, `N_TRIALS_CAT`) и `RANDOM_STATE`,
* наборы окон для лагов и индикаторов (`LAGS`, `ROLL_WINDOWS`, `ATR_WINDOWS`, `RSI_PERIODS`).

### Шаг 1. Загрузка и приведение данных к ожидаемому формату

Функция `load_prices()`:

* читает `data/prices_all.csv`,
* пытается «нормализовать» названия колонок (например, `Date`, `date`, `DATE` → `date`),
* приводит `date` к типу `datetime`.

Функция `pick_price_col()`:

* выбирает, какую колонку считать ценой (`Adj Close`, если есть, иначе `Close`).

### Шаг 2. Фильтрация тикеров по полноте истории

Функция `filter_tickers_starting_at_global_min()`:

* находит глобальную минимальную дату в датасете,
* оставляет только те тикеры, у которых первая доступная дата совпадает с этой глобальной.

Зачем: чтобы панель признаков строилась на сопоставимой длине истории и не было «коротких» тикеров, портящих распределение фичей.

### Шаг 3. Перевод дневных OHLCV в месячные OHLCV

`make_monthly_ohlcv()` делает pivot по `Ticker` и ресемплинг на конец месяца:

* `Open`  → первый день месяца,
* `High`  → максимум за месяц,
* `Low`   → минимум за месяц,
* `Close`/`Adj Close` → последняя цена месяца,
* `Volume` → сумма объёмов за месяц.

В итоге получается набор месячных матриц (индекс = дата, колонки = тикеры).

### Шаг 4. Целевая переменная и базовые ряды

В `make_monthly_panel()`:

* берётся месячная цена `Price`,
* строится лог-цена `ln(P)` и месячная лог-доходность `ret = Δ ln(P)`,
* строится рыночный фактор `mkt_ret` как средняя месячная доходность по тикерам (equal-weight),
* добавляются календарные циклические признаки `month_sin`/`month_cos`,
* таргет задаётся как `target_next = ret.shift(-1)` — то есть «что будет в следующем месяце».

Важно: модель предсказывает **доходность**, а не цену. Если нужно восстановить прогноз цены — это отдельный шаг (кумуляция доходностей).

### Шаг 5. Инженерия признаков

Для каждого тикера формируется таблица признаков по месяцам:

1. **Лаги доходностей**: `ret_lag{L}` для `L` из `LAGS`.

2. **Rolling-статистики по доходностям** для окон из `ROLL_WINDOWS`:

* `ret_roll_mean_{W}` — средняя,
* `ret_roll_std_{W}` — стандартное отклонение,
* `ret_mom_{W}` — моментум как сумма доходностей за окно.

3. **ATR (Wilder)** из OHLC:

* `TR = max(High-Low, |High-PrevClose|, |Low-PrevClose|)`,
* далее сглаживание Уайлдера: `EMA(alpha=1/W)`.

4. **RSI (Wilder)** на лог-доходностях:

* сглаженные средние положительных и отрицательных изменений,
* `RSI = 100 - 100/(1+RS)`.

5. **Объёмы (если есть)**:

* `vol_dln_1` — лог-изменение объёма,
* `vol_roll_std_{W}` — rolling std лог-изменения объёма.

6. **Рыночный фактор** и его лаги:

* `mkt_ret` и `mkt_ret_lag{L}` для лагов `[1, 3, 6, 12]`.

После этого делается `dropna()` (из-за лагов/rolling первых наблюдений всегда не хватает) и всё собирается в один общий `panel`.

### Шаг 6. Разбиение на Train/Test/Valid

`split_periods(panel)`:

* Train: `date <= TRAIN_END`
* Test: `date.year == TEST_YEAR`
* Valid: `date.year == VAL_YEAR`

Признаки (`feat_cols`) — все колонки, кроме `date`, `Ticker`, `target_next`.

### Шаг 7. Подбор гиперпараметров Optuna

#### XGBoost (`optuna_xgb`)

* Внутри Train берётся hold-out: **последние 12 месяцев** как валидация, остальное — обучение.
* Optuna минимизирует RMSE на этом hold-out.
* Обучение идёт на GPU: `device=cuda`, `tree_method=hist`.

#### CatBoost (`optuna_cat`)

* Аналогично: hold-out последние 12 месяцев внутри Train.
* Оптимизация RMSE.
* GPU-режим: `task_type=GPU`, плюс параметры регуляризации/бэггинга/переполнения.

### Шаг 8. Обучение финальных моделей на полном Train

* `fit_xgb_full()` обучает XGB на всём Train с лучшими параметрами.
* `fit_cat_full()` обучает CatBoost на всём Train с лучшими параметрами.

### Шаг 9. «Онлайн»-прогнозирование по месяцам

Идея: максимально приближенно к реальности — мы каждый месяц делаем прогноз, а затем «узнаём факт» и добавляем этот месяц в обучающие данные.

#### XGBoost (`online_predict_xgb`)

Для каждого месяца:

1. предсказываем текущий месяц (по строкам `cur`),
2. добавляем `cur` в накопленный train,
3. делаем **incremental update** через `xgb.train(..., xgb_model=model)` на `num_boost_round=100`.

Обрати внимание: это не “полное переобучение”, а доращивание бустинга поверх существующей модели.

#### CatBoost (`online_predict_cat`)

Для каждого месяца:

1. предсказываем,
2. добавляем месяц в накопленный train,
3. переобучаем модель заново, используя внутри накопленного train тот же принцип hold-out на последние 12 месяцев
   (если данных мало — обучается без eval_set).

Обрати внимание: здесь **переобучение** (ре-тренинг), а не инкрементальное дообучение.

### Шаг 10. Оценка качества и сохранение результатов

Метрики считаются отдельно для Test-2023 и Valid-2024:

* RMSE, MAE, R2.

Сохраняется:

* предсказания XGB и CatBoost в `forecasts/*.csv`,
* сводная таблица метрик в `forecasts/summary_metrics.csv`.

## 2) Входные данные

Обязательные колонки:

В коде есть фильтр: остаются только тикеры, чья **первая дата** равна **глобальной минимальной дате** в датасете. Это убирает тикеры с укороченной историей.

## 8) Частые проблемы

### 1) Не найден файл `data/prices_all.csv`

Проверь:

* файл лежит в `data/`
* имя `prices_all.csv` совпадает

### 2) Ошибки CatBoost GPU / XGBoost CUDA

Обычно причины:

* несовместимость драйвера NVIDIA и CUDA
* неподходящая сборка пакетов
* контейнер без проброса GPU

Быстрый тест:

```bash
python -c "import xgboost as xgb; print(xgb.__version__)"
python -c "from catboost import CatBoostRegressor; print('cat ok')"
```

### 3) Слишком мало данных после `dropna()`

Лаги/rolling/ATR/RSI отбрасывают первые месяцы. Если истории мало — датасет может стать слишком коротким.

---

## 9) Идеи для расширения

* сохранить feature importance (XGB + CatBoost)
* метрики по тикерам (где модель лучше/хуже)
* wide-формат предсказаний (дата × тикер)
* более “true online” режим для CatBoost через `init_model` (при необходимости)
