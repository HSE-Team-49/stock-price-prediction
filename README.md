# Прогноз месячной доходности акций (по тикеру отдельная модель)

Этот скрипт строит **месячные признаки** по дневным OHLCV-данным, затем обучает **отдельную модель на каждый тикер** и оценивает качество на **целевых месяцах тестового года** (по умолчанию 2024) в режиме **walk-forward expanding window**.

Главная идея: для каждого тикера мы имитируем реальную торговую/прогнозную ситуацию — на каждом месяце теста обучаем модель **только на данных, доступных до этого месяца**, делаем прогноз, затем двигаемся дальше.

---

## 1) Что делает код — по шагам

### 1.1 Входные данные

Скрипт читает файл:

* `data/prices_all.csv`

Ожидаемые колонки (названия могут быть в другом регистре/с пробелами — код попробует переименовать):

* `date` — дата (дневная)
* `Ticker` — тикер
* `Open`, `High`, `Low`, `Close`, `Adj Close` (опционально), `Volume` (опционально)

**Цена для расчёта доходностей** выбирается так:

* если есть `Adj Close` — используется он,
* иначе используется `Close`.

### 1.2 Фильтрация тикеров

Функция `filter_tickers_starting_at_global_min` оставляет только те тикеры, у которых **первая дата совпадает с глобальной минимальной датой по всему датасету**.

Зачем это сделано:

* чтобы все тикеры начинались «с одного старта»,
* чтобы не было ситуации, когда у части тикеров история короче и после построения лагов/rolling остаётся совсем мало данных.

> Если хочешь оставить все тикеры — можно отключить этот шаг.

### 1.3 Агрегация дневных данных в месячные

Функция `make_monthly_ohlcv` делает ресемплинг дневных OHLCV в месячные:

* `Open` — первое значение в месяце
* `High` — максимум за месяц
* `Low` — минимум за месяц
* `Close`/`Adj Close` — последнее значение в месяце
* `Volume` — сумма объёмов за месяц

Дальше создаётся `Price` — выбранная ценовая колонка.

### 1.4 Целевая переменная (что предсказываем)

Скрипт работает с лог-доходностями:

* `lnp = ln(Price)`
* `ret(t) = lnp(t) - lnp(t-1)`

Цель:

* `target_next = ret(t+1)`

То есть признаки строятся на месяце **t**, а модель предсказывает доходность **следующего месяца**.

Дополнительно вводится:

* `target_month = month(t+1)` — **целевой месяц**, к которому относится прогноз.

Это важно для разбиения train/test:

* если `TEST_YEAR = 2024`, то тест — это все строки, где `target_month` попадает в 2024.

### 1.5 Признаки (features) — подробно

Ниже — полный разбор того, **какие признаки** создаются в `make_monthly_panel`, **что они означают** и **как привязаны по времени**.

Ключевая идея тайм-алайна (временного выравнивания):

* признаки считаются на месяце **t** (это колонка `date`),
* цель — `target_next = ret(t+1)`,
* прогноз относится к **целевому месяцу** `target_month = t+1`.

То есть модель на вход получает информацию, доступную до конца месяца t, и предсказывает доходность следующего месяца.

#### Базовый ряд: лог-доходность

Для каждого тикера строится ряд:

* `Price(t)` — месячная цена (обычно `Adj Close`, иначе `Close`)
* `lnp(t) = ln(Price(t))`
* `ret(t) = lnp(t) - lnp(t-1)`

Это приблизительно соответствует «процентной доходности», но в лог-форме (удобнее складывается во времени).

> В коде `ret` — это уже месячная лог-доходность, рассчитанная после ресемплинга в месяцы.

---

### A) Лаги доходности тикера (autoregressive часть)

Колонки:

* `ret_lag1`, `ret_lag2`, `ret_lag3`, `ret_lag6`, `ret_lag9`, `ret_lag12`

Смысл:

* это прошлые значения `ret` для этого тикера.

Формально:

* `ret_lagL(t) = ret(t-L)`

Зачем:

* если у доходностей есть автокорреляция (пусть даже слабая), модель может её использовать;
* лаг 12 часто ловит сезонность/годовые эффекты.

---

### B) Rolling-статистики по доходности тикера

Окна задаются `ROLL_WINDOWS = [3, 6, 12]`.

Для каждого окна W строится три вида признаков:

1. `ret_roll_mean_W` — средняя доходность за последние W месяцев

* `mean_W(t) = (1/W) * Σ_{k=0..W-1} ret(t-k)`

Интуиция:

* «средний дрейф» за квартал/полгода/год.

2. `ret_roll_std_W` — волатильность (стандартное отклонение) доходностей

* `std_W(t) = std( ret(t), ret(t-1), …, ret(t-W+1) )`

Интуиция:

* текущий режим риска/турбулентности.

3. `ret_mom_W` — моментум как сумма лог-доходностей

* `mom_W(t) = Σ_{k=0..W-1} ret(t-k)`

Интуиция:

* за W месяцев это примерно `ln(Price(t)/Price(t-W))` — то есть накопленный рост/падение.

---

### C) ATR (Average True Range, Уайлдер) — «амплитуда движения»

Строится только если есть месячные `High`, `Low`, `Close`.
Окна: `ATR_WINDOWS = [6, 12]`.

Сначала для каждого месяца t считается True Range (TR):

* `TR(t) = max( High(t)-Low(t), |High(t)-Close(t-1)|, |Low(t)-Close(t-1)| )`

Дальше ATR — сглаживание Уайлдера (эквивалент EMA с `alpha = 1/ws`):

* `ATR_ws(t) = EMA(TR, alpha=1/ws)`

Колонки:

* `atr_6`, `atr_12`

Интуиция:

* ATR больше похож на «абсолютную» амплитуду движений, а не на доходность;
* помогает модели понять, когда рынок «раскачан» даже при нулевой средней доходности.

Замечание:

* ATR здесь в **ценовых единицах**, а не в процентах. При желании можно нормализовать, например `ATR/Price`.

---

### D) RSI (Relative Strength Index, Уайлдер) — «перегретость/перепроданность»

Окна: `RSI_PERIODS = [6, 12]`.

Классический RSI строится по изменениям цены. В коде он считается по `ret(t)` (лог-доходностям), что по смыслу эквивалентно.

Идея:

* разделяем изменения на «плюсы» и «минусы»,
* сглаживаем их Уайлдером,
* берём отношение.

В коде:

* `gain = EMA(max(ret, 0), alpha=1/period)`
* `loss = EMA(max(-ret, 0), alpha=1/period)`
* `RS = gain / loss`
* `RSI = 100 - 100/(1+RS)`

Колонки:

* `rsi_6`, `rsi_12`

Интуиция:

* RSI ближе к «состоянию импульса» и часто ловит развороты/перекупленность.

---

### E) Признаки по объёму (Volume)

Строятся только если есть месячный `Volume`.

1. `vol_dln_1` — изменение лог-объёма

* `lnV(t) = ln(Volume(t))`
* `vol_dln_1(t) = lnV(t) - lnV(t-1)`

Интуиция:

* «всплески интереса» / ликвидность.

2. `vol_roll_std_W` — волатильность объёма по окнам 3/6/12

* `std( vol_dln_1(t), …, vol_dln_1(t-W+1) )`

Интуиция:

* режим ликвидности: стабильный/нервный.

---

### F) Рыночный фактор (market factor) и его лаги

Строится по всем тикерам как **equal-weight средняя** месячная доходность:

* `mkt_ret(t) = mean_tickers( ret_ticker(t) )`

Колонки:

* `mkt_ret`
* `mkt_ret_lag1`, `mkt_ret_lag3`, `mkt_ret_lag6`, `mkt_ret_lag12`

Зачем:

* это простейшая версия «рыночного фактора» (аналог broad market движения),
* модель может отделять: «тикер вырос потому что вырос рынок» vs «тикер вырос сам по себе».

Важно:

* в текущей реализации `mkt_ret` считается по всем тикерам сразу, без исключения самого тикера.
  На практике эффект маленький, но если хочешь строго — можно считать market factor как среднее по тикерам **кроме текущего**.

---

### G) Календарные циклические признаки

Колонки:

* `month_sin`, `month_cos`

Считаются от номера месяца `m = 1..12`:

* `month_sin = sin(2π m/12)`
* `month_cos = cos(2π m/12)`

Зачем:

* модель получает мягкую сезонность (январь близко к декабрю, а не “далеко”).

---

### H) Почему после фичей много строк отбрасывается

Лаги, rolling и индикаторы требуют истории. Поэтому первые месяцы для каждого тикера имеют NaN и удаляются:

* для `ret_lag12` нужно минимум 12 прошлых месяцев,
* для `ret_roll_*_12` нужно минимум 12 наблюдений,
* RSI/ATR тоже требуют «разгона» сглаживания.

Это нормально: модель начинает «жить» только после того, как накопилась достаточная история.

### I) Итоговая табличка (важные колонки)

На выходе `make_monthly_panel` даёт:

* `date` — месяц признаков (t)
* `target_month` — целевой месяц (t+1) **для разбиения train/test**
* `Ticker`
* `target_next` — целевая доходность `ret(t+1)`
* остальные колонки — признаки

## 2) Логика обучения и тестирования

### 2.1 Почему «test = 2024» задаётся через `target_month`

Мы прогнозируем `ret(t+1)`, поэтому прогноз относится к **следующему месяцу**.

Пример:

* признаки построены на январе 2024 (`date = 2024-01`),
* цель — доходность февраля 2024,
* значит эта строка относится к `target_month = 2024-02`.

Поэтому корректнее считать тестом именно **целевые месяцы**.

### 2.2 Для каждого тикера — своя модель

Внешний цикл идёт по тикерам. Для каждого тикера:

1. **Train для подбора гиперпараметров (Optuna):**

   * все строки, у которых `target_month.year < TEST_YEAR`.

2. **Hold-out внутри train:**

   * последние `HOLDOUT_MONTHS` целевых месяцев откладываются как валидация Optuna.
   * это нужно, чтобы Optuna подбирала гиперпараметры, ориентируясь на «последнюю историю», похожую на будущий тест.

3. **Walk-forward expanding window на тестовом годе:**

   * берём каждый `target_month` тестового года по порядку,
   * обучаем модель **с нуля** на всех `target_month < текущего`,
   * предсказываем для текущего `target_month`,
   * сохраняем прогноз.

Ключевой момент: модель **не дообучается инкрементально**, а каждый раз переобучается на расширяющемся окне.

Почему так:

* это простая и прозрачная схема,
* избегаем скрытых побочных эффектов «частичного дообучения»,
* легко понимать, «в какие моменты меняются веса» — **на каждом тестовом месяце**.

## 3) Модели

Скрипт поддерживает два варианта:

### 3.1 XGBoost (`MODEL_KIND = "xgb"`)

* Рекомендуется как базовый вариант: обычно быстрее.
* Подбор гиперпараметров Optuna:

  * `max_depth`, `min_child_weight`, `subsample`, `colsample_bytree`, `eta`, `gamma`, `lambda`, `alpha`, `max_bin`
  * и `num_boost_round`.

GPU:

* при `USE_GPU_XGB = True` используется `device=cuda` и `tree_method=hist`.

### 3.2 CatBoost (`MODEL_KIND = "cat"`)

* Optuna подбирает:

  * `depth`, `learning_rate`, `l2_leaf_reg`, `bagging_temperature`, `random_strength`, `bootstrap_type`, `border_count`, `od_wait`, `iterations`.

GPU:

* при `USE_GPU_CAT = True` используется `task_type=GPU`, `devices=0`.

## 4) Кэш гиперпараметров Optuna

После подбора гиперпараметров для тикера они сохраняются в:

* `forecasts/optuna_params/`

Файлы выглядят так:

* `xgb_params_<TICKER>.json`
* `cat_params_<TICKER>.json`

При следующем запуске, если файл параметров уже есть, Optuna для этого тикера **не запускается**.

Это сильно ускоряет повторные прогоны.

## 7) Настройки, которые обычно меняют

В начале файла:

* `TEST_YEAR` — год теста (целевые месяцы)
* `MODEL_KIND` — `"xgb"` или `"cat"`
* `N_TRIALS_XGB`, `N_TRIALS_CAT` — число trial’ов Optuna
* `HOLDOUT_MONTHS` — сколько целевых месяцев держать под hold-out в Optuna
* `USE_GPU_XGB`, `USE_GPU_CAT` — включить/выключить GPU

Фичи:

* `LAGS`, `ROLL_WINDOWS`, `ATR_WINDOWS`, `RSI_PERIODS`

Логи:

* `LOG_EVERY_TICKER`, `LOG_EVERY_MONTH`

---

## 8) Как понимать логику «веса меняются»

В этом варианте веса модели меняются только в двух местах:

1. **Optuna-подбор** — много раз обучаемся на train/holdout, но это только для выбора гиперпараметров.

2. **Walk-forward на тестовом годе** — для каждого `target_month` теста:

   * обучаем модель **заново** на всех предыдущих месяцах,
   * делаем прогноз,
   * переходим к следующему месяцу.

То есть на тесте веса обновляются **каждый месяц**.
