# Поиск сезонности в акциях через автоэнкодер и FFT

## Краткое описание

Данный скрипт предназначен для поиска сезонных и циклических компонент в ценовых рядах акций и в рядах логарифмических доходностей.

Итоговая версия является развитием исходного скрипта, который был написан под RTX 2060. Новая версия адаптирована под NVIDIA H100/A100. 
Основной пайплайн:

1. Загрузка длинной таблицы с котировками.
2. Подготовка рядов по каждому тикеру.
3. Нормализация логарифмов цен и логарифмических доходностей.
4. Построение скользящих окон.
5. Обучение автоэнкодера с подбором гиперпараметров через Optuna.
6. Реконструкция временных рядов через автоэнкодер.
7. Расчёт FFT-спектров для исходных рядов и AE-реконструкций.
8. Поиск доминирующих периодов.
9. Сохранение summary-таблиц, общих периодов, спектров и графиков.

---

## Формат входных данных

Финальная версия рассчитана на файл формата:

```text
date,Ticker,Open,High,Low,Close,Volume
```

Пример:

```text
date,Ticker,Open,High,Low,Close,Volume
2025-11-24 00:00:00,ABBV,236,237.6199951171875,228.47999572753906,229.50999450683594,10225900
2025-11-24 00:00:00,BA,180.30999755859375,180.30999755859375,177.3000030517578,179.1199951171875,9386000
```

В коде используются следующие колонки:

```python
USER_DATE_COL = "date"
USER_TICKER_COL = "Ticker"
USER_PRICE_COL = "Close"
```

Колонки `Open`, `High`, `Low`, `Volume` в текущей версии не используются в расчётах, но могут быть сохранены во входном файле.

### 4. Ускорение CPU-частей через joblib

Через `joblib.Parallel` распараллелены следующие этапы:

1. Подготовка рядов по тикерам.
2. Построение скользящих окон.
3. Расчёт FFT и поиск пиков по тикерам.

Параметры:

```python
USER_CPU_N_JOBS = 30
USER_JOBLIB_BATCH_SIZE = 16
```

`USER_CPU_N_JOBS` задаёт количество процессов `joblib`.

---

### 5. Ускорение отдельных CPU-циклов через Numba

В финальной версии добавлены `numba`-функции:

```python
@njit(cache=True)
def _estimate_prominence_simple(...)
```

```python
@njit(cache=True)
def _top_peaks_numba(...)
```

```python
@njit(parallel=True, cache=True)
def _overlap_average_from_window_outputs(...)
```

Не переносились в Numba:

- `pandas.DataFrame`-операции;
- `matplotlib`;
- `ExcelWriter`;
- `torch`-инференс;
- `np.fft.rfft` внутри одного ряда.

Для FFT выбран другой подход: считать FFT параллельно по тикерам.

---

### 6. Оптимизация построения окон

В исходной версии окна строились через Python-цикл:

```python
for j in range(len(x) - window_size + 1):
    all_windows.append(x[j:j + window_size])
```

В финальной версии используется:

```python
np.lib.stride_tricks.sliding_window_view
```

Это быстрее и компактнее по коду. Построение окон дополнительно распараллелено по рядам.

---

### 7. Батчевая реконструкция AE

В исходной версии реконструкция ряда выполнялась по одному окну:

```python
for i in range(n - window_size + 1):
    inp = torch.from_numpy(window).unsqueeze(0).to(DEVICE)
    out = model(inp)
```

В финальной версии окна передаются в модель большими батчами:

```python
USER_RECON_BATCH_SIZE = 32768
```

После получения выходов автоэнкодера перекрывающиеся окна собираются обратно в ряд через Numba-функцию `_overlap_average_from_window_outputs`.

---

### 8. Расширение FFT-анализа

В исходной версии FFT считался только по AE-реконструкции.

В финальной версии анализируются два источника:

```text
raw       — исходный нормированный ряд
ae_recon  — реконструкция автоэнкодера
```

Это позволяет проверить, не создаёт ли автоэнкодер искусственную сезонность.

Если доминирующие периоды в `raw` и `ae_recon` близки, это усиливает доверие к результату.

---

### 9. Больше доминирующих периодов

В исходной версии использовалось:

```python
TOP_K = 3
```

В финальной версии:

```python
USER_TOP_K = 5
```

Это позволяет видеть не только главный пик, но и несколько вторичных циклов.

### Автоэнкодер

Модель:

```python
class Autoencoder(nn.Module)
```

Архитектура подбирается через Optuna:

```python
latent_dim: 8–128
hidden_dim: 128–1024
n_layers: 1–5
dropout: 0.0–0.35
lr: 1e-5–3e-3
batch_size: 1024–32768
n_epochs: 20–80
```

Используется `AdamW` и `MSELoss`.

---

### Обучение с Optuna

Основные функции:

```python
optuna_objective(...)
train_autoencoder_with_optuna(...)
```

В финальной версии:

```python
USER_N_TRIALS = 300
USER_OPTUNA_N_JOBS = 1
```

### Реконструкция через AE

Основная функция:

```python
reconstruct_series_with_ae(...)
```

Она:

1. строит скользящие окна для одного тикера;
2. прогоняет окна через AE батчами на GPU;
3. собирает перекрывающиеся выходы обратно в один ряд через Numba.

Основные функции:

```python
compute_periodogram(...)
```

Для каждого пика сохраняются:

### Доходности

Для логарифмических доходностей результат изменился сильнее.

Старый прогон показывал почти универсальную короткую сезонность около 2–3 торговых дней. Новый прогон показывает, что такие пики действительно могут встречаться, но их вклад в спектральную мощность мал.

Итоговая интерпретация:

> Для логарифмических доходностей устойчивый сезонный компонент выражен существенно слабее, чем для ценовых рядов. Обнаруживаемые короткие периоды порядка 2–10 торговых дней имеют низкую долю спектральной мощности и могут отражать шумовые или микроструктурные эффекты, а не устойчивую сезонность.

## Итоговый вывод

Финальная версия является основной и наиболее удачной версией пайплайна.

Преимущества финальной версии:

1. Поддерживает новый формат входного файла.
2. Все настройки вынесены в один блок.
3. Эффективнее использует H100/A100.
4. Не параллелит GPU и избегает конфликтов CUDA-процессов.
5. Распараллеливает CPU-части через `joblib`.
6. Использует Numba для плотных численных циклов.
7. Быстрее строит окна через `sliding_window_view`.
8. Реконструирует ряды через AE батчами.
9. Сравнивает `raw` и `ae_recon` FFT-спектры.
10. Сохраняет агрегированные common periods.
11. Существенно улучшает качество автоэнкодера.
12. Даёт более реалистичную интерпретацию сезонности в доходностях.

Главный содержательный результат:

- в ценах акций сохраняются устойчивые средне- и долгосрочные циклы;
- в доходностях сильная сезонность не подтверждается, а короткие периоды имеют низкую спектральную мощность.
